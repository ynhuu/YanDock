# YanDock · 虤坞

**把开发机器上的 AI Coding CLI，带到你的浏览器。**

YanDock 是一个单用户、自托管的远程开发工作台。在电脑、手机或平板上打开浏览器，即可操作开发机器上的 Shell 与 AI Coding CLI，查看 Git 更改、浏览项目文件，并在切换设备后继续终端会话。

CLI 和开发环境留在你的机器上，浏览器负责交互。保留真实终端的使用方式，不替代 CLI，也不试图成为完整 IDE。

[使用与部署](docs/使用指南.md) · [安装与卸载](docs/安装脚本.md) · [技术方案](docs/技术方案.md)

> **开发预览**：当前仍在完善平台与移动真机验收，不建议用于公网生产环境。

## 快速安装

macOS / Linux 快捷安装（默认下载最新 Release，会直接执行公开仓库中的安装脚本；需要交互终端）：

```sh
curl -fsSL https://raw.githubusercontent.com/ynhuu/YanDock/main/scripts/install.sh | bash -s -- install
```

Release 需包含本机平台的 ZIP 资产和 `SHA256SUMS`。如需先检查脚本，再下载后运行，见[安装与卸载](docs/安装脚本.md)。

## 为什么选择 YanDock

- **随时打开终端**：无需在每台设备上配置开发环境，用浏览器连接同一台开发机器。
- **断开连接，不中断工作**：浏览器断线不默认结束服务端终端进程；重新连接后回放最近输出，继续操作。
- **终端之外，保留必要上下文**：文件面板跟随当前终端目录，不离开工作台即可查看代码、文档和 Git 差异。
- **照顾小屏幕操作**：为手机和平板提供辅助键、触摸滚动、复制粘贴与软键盘布局适配。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 浏览器终端 | 基于 PTY、WebSocket 与 xterm.js，传输真实终端的输入、输出和尺寸变化 |
| 多终端会话 | 独立终端、标签切换与排序、状态展示和关闭操作，切换标签不重建终端 |
| 跨设备接续 | 新设备登录后撤销旧登录，保留服务端终端进程，恢复最近输出后继续操作 |
| Git 更改 | 跟随当前终端目录，查看文件状态、增删行数、逐文件差异和按需加载的提交历史图 |
| 项目文件 | 目录树、代码 / Markdown / 图片预览，以及文件上传、下载和删除；单文件下载上限 128 MiB |
| 移动端交互 | 响应式布局、辅助键栏、触摸滚动、长按复制粘贴和软键盘避让 |
| 轻量自托管 | 网页嵌入 Go 可执行文件，部署在运行 CLI 的开发机器上 |

## 工作方式

```text
电脑 / 手机 / 平板浏览器
          │
      HTTPS / WSS
          │
    HTTPS 反向代理
          │
   YanDock · 开发机器
          ├── 终端会话 → Shell / AI Coding CLI
          └── 项目文件与 Git 更改
```

YanDock 面向**一个人、一台开发机器、多个终端会话**。CLI、依赖与供应商凭据由服务端环境管理，浏览器无需安装对应 CLI。

## 当前状态与边界

- **CLI 接入**：当前使用通用程序入口启动 Shell 或 CLI；Pi、OpenCode、Codex 的专用适配尚未完成，不代表这些 CLI 已完成兼容性验收。
- **会话恢复**：支持断线、刷新和换设备后的有界内存输出回放；不是完整终端快照，也不提供无限历史。服务重启会清除登录态、终端会话与回放数据。
- **设备控制**：仅保留最新成功登录，每个终端只有一个交互控制连接；不提供多设备同时控制或画面广播。
- **平台支持**：Linux 与 macOS 为首版支持目标，macOS 包含 arm64 和 amd64。目前主要在 macOS arm64 上进行自动化运行验证，Linux、macOS amd64 及移动真机验收尚未完成。
- **使用范围**：尚无多项目管理，不提供 Windows 支持、多租户隔离或完整 IDE。远程部署要求认证及 HTTPS/WSS，不应向不可信用户开放终端。

详细实现与验收范围见[技术方案](docs/技术方案.md)。
