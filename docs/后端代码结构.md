# 后端开发指南

后端沿用 Go 标准库 `net/http`，按现有职责划分包，在包内拆分文件；不增加无实际需求的 service/repository 层或接口。

启动、凭据、停止与部署见[使用指南](使用指南.md)，接口字段、状态码和资源限额见[终端协议](终端协议.md)，架构与后续目标见[技术方案](技术方案.md)。

[目录与职责](#1-目录与职责) · [资源所有权](#2-依赖与资源所有权) · [生命周期与同步](#3-生命周期与同步约定) · [检查与构建](#4-检查与构建) · [测试服务维护](#5-测试服务维护)

初次开发可先阅读目录图，再跳到检查与构建。修改认证、PTY 或 WebSocket 前，请先确认以下约定：

- **PTY 归会话管理器所有**，浏览器连接关闭不等于会话关闭。
- **请求取消不能终止后台会话**，进程、连接和输出流各自有明确的清理路径。
- **先构建网页，再编译 Go**，二进制使用编译时嵌入的前端资源。

## 2. 依赖与资源所有权

- `cmd/yandock` 组装 `auth`、`session`、`server` 和 `webassets`，管理服务启动与退出。
- `server` 依赖 `auth`、`session`，但不拥有 PTY 或子进程；其他业务包不反向依赖 `server`。
- `auth` 只保留最新登录；成功替换或注销时关闭其撤销信号，WebSocket 主动断开旧登录的连接，不关闭终端进程。登录过期仍由输入和心跳检查发现。
- `session.Manager` 拥有会话及其进程。创建成功后注册会话，再启动读取与进程等待 goroutine；启动失败时清理已取得的资源。
- `Manager.mu` 保护注册表、显示编号分配、创建顺序与关闭状态；新建时复用最小空闲编号，等待单个会话关闭时不持有注册表锁。
- `Session.mu` 保护运行、输出、回放和目录查询状态，`inputMu` 串行化写入与 resize。目录查询采用短时缓存及并发合并；等待请求的取消不用于结束后台会话。
- WebSocket 输入读取与输出循环共享可取消 context；退出时取消、关闭连接并等待读取 goroutine，最后释放控制连接占用。浏览器断线不关闭会话。
- 登录限流、每会话单控制连接、消息与缓冲大小约束不因文件拆分而改变；终端会话总数不设置应用层上限。

## 3. 生命周期与同步约定

- `auth.Watch` 在锁内验证 Cookie，返回当前登录的撤销信号；`Valid` 复用该校验。凭据验证和随机登录 ID 生成成功后才替换旧状态，失败登录不踢人。
- 监听仅由 `--listen` 决定。来源检查基于请求 Host 与 HTTP/HTTPS Origin，反向代理需保留外部 Host；Cookie 的 Secure 属性按 TLS 或已校验的 HTTPS Origin 设置，登录与注销一致，不保存全局网络模式或配置来源。
- `terminal.go` 在申请控制连接前再次验证登录。输入循环串行处理输入与 resize，输出循环监听撤销、心跳与输出；登录失效关闭码为 `4001`，输入/协议错误为 `1008`。
- `Session.Attach` 在锁内返回实时输出 channel、不可变回放快照和脱离函数；握手失败也必须脱离；仅在成功发送 hello 后调用 `ConfirmAttach` 标记已连接，失败升级不消耗首次启动查询。连接关闭、输入循环退出与控制位置释放有先后关系，新登录连接短暂遇到 `409` 时按既有退避重试。
- `process.go` 不使用请求 context 启动进程。自然退出后等待输出排空再关闭 PTY，显式关闭先终止进程组，必要时强制终止；服务退出由管理器统一关闭。
- 自然退出的记录保留到显式移除，仍占用显示编号。`List` 按创建顺序返回，不能把显示编号当成时间顺序或会话唯一标识。
- 创建接口使用浏览器提交的有效初始行列数启动 PTY，不替客户端猜测网格；后续 resize 仍通过同一输入锁串行处理。`replay.go` 按安全分段保留最近输出及尺寸事件，并限制数据量和帧数；断线后继续采集，服务重启或移除时清除。
- `project_paths.go` 为文件和 Git 接口提供同一套受限根目录与路径规则，拒绝符号链接、越界和 `.git` 路径。`project_files.go` 负责文件 HTTP 语义和上传不覆盖规则；`project_git.go` 负责 Git 参数列表执行、时间与输出限制；`project_git_stats.go` 维护未跟踪文件的单文件及请求总读取预算。这些限制不构成 Shell 沙箱。
- HTTP 错误响应为纯文本，结构化成功响应为 JSON；预览和下载返回文件正文，上传成功为无正文 `201`，其他无正文操作按接口返回 `204`；不把内部启动错误、凭据或环境内容直接返回给浏览器。`decodeJSON` 供 HTTP 和 WebSocket 控制消息共用，大小限制分别由传输层处理。

## 4. 检查与构建

从项目根目录执行。前端依赖需先按[前端文档](../web/README.md#4-本地开发)安装，不能用空网页替代缺失构建：

```sh
pnpm --dir web build
go test ./...
go vet ./...
go test -race ./...
go build ./...
```

`server` 和 `session` 的集成测试需要本机可运行的 `sh` 和 PTY，Git 项目测试还需要可用的 `git`。认证测试使用可控时钟，覆盖过期、限流、最新登录、并发登录及撤销；集成测试覆盖 HTTP/Origin、严格协议、控制冲突、失败升级、连接注销、进程存活、有界回放及尺寸事件、输出上限、编号复用，以及文件读写与统计预算。前端类型、lint、格式和浏览器检查见[前端文档](../web/README.md#5-检查与测试)。

当前主要在 macOS arm64 验证 Go 单元/集成测试、vet、race 与构建。其他平台不能用本机测试结果代替；修改 PTY、syscall 或进程组行为时，应单独记录 Linux、macOS arm64/amd64 的编译及运行结果。交叉编译成功不等于目标平台生命周期验收通过。

### Makefile 构建入口

依赖安装完成后，在项目根目录执行：

```sh
make                 # 当前平台，输出 bin/yandock
make release         # 构建五个平台 ZIP 资产及 SHA256SUMS
make linux-armv7     # bin/yandock-linux-armv7，GOOS=linux GOARCH=arm GOARM=7
make linux-arm64     # bin/yandock-linux-arm64
make linux-amd64     # bin/yandock-linux-amd64
make darwin-arm64    # bin/yandock-darwin-arm64，适用于 Apple Silicon
make darwin-amd64    # bin/yandock-darwin-amd64，适用于 Intel Mac
```

每个二进制目标都会先构建并同步前端嵌入资源，然后生成对应 ZIP，ZIP 内的二进制保留平台架构名；`make -j release` 也只执行一次前端构建，再并行编译五个目标，最后生成 `SHA256SUMS`。交叉编译设置 `CGO_ENABLED=0`，ARMv7 目标需要支持 ARMv7 硬浮点的 Linux 用户空间，不是 ARM64 或 ARMv6 版本。打包需要 `zip`，安装 ZIP 资产需要 `unzip`。

`make help` 查看目标；可使用 `make release OUT_DIR=bin/release VERSION=v1.2.3` 修改输出目录并注入发布版本，也可覆盖 `GO`、`PNPM` 指定工具。`VERSION` 默认是 `dev`，二进制可用 `-v` 显示版本。Makefile 不会自动安装依赖、运行测试、启动或重启服务，也不会创建或上传 GitHub Release。产物无需携带前端文件，但仍依赖目标机器上的 Shell 或 CLI。这些目标只定义构建方式，不代表各平台已完成真机运行验收。

## 5. 测试服务维护

业务改动完成检查后，应重建嵌入网页和 Go 二进制，再更新已确认身份的测试服务；先告知登录态和终端会话会丢失，保留原工作目录、启动参数和必要环境，不输出或保存凭据。检查端口、首页、新资源与未认证 API 的保护行为。

仅文档修改不重启服务。运行与重启步骤统一见[使用指南](使用指南.md#7-更新停止与重启)，Agent 的执行规则以根目录 [AGENTS.md](../AGENTS.md) 为准。
