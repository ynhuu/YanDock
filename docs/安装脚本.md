# 自动安装与卸载脚本

`scripts/install.sh` 是交互式安装器：默认从 `ynhuu/YanDock` 最新 GitHub Release 下载 ZIP 资产及 SHA-256 清单，校验压缩包后提取对应平台的可执行文件并安装，经确认后启用后台自启动；可用 `--repo` 覆盖仓库。运行程序不需要 Go、Node.js 或 pnpm，但目标机器仍需具备 `unzip`、所配置 Shell/CLI 的运行环境；Git 更改与差异面板还需要启动 PATH 中可找到 `git`。

> **开发预览**：尚未验收真实 Release 下载和真实后台服务安装。请先了解下方验证范围，再决定是否使用安装器。脚本不会创建 GitHub Release 或上传文件。

## 1. 使用前提

- macOS 使用用户级 launchd；Ubuntu、Debian 使用正在运行的 systemd；Alpine 使用正在运行的 OpenRC。容器中没有对应服务管理器时会拒绝安装。
- 服务默认以执行用户运行，允许直接由 root 安装。通过普通用户的 `sudo` 调用时，仍降权为 `SUDO_USER` 后再下载、安装，不自动将服务提升为 root。直接 root 执行时会明确警告：服务及其终端具有完整系统权限。
- Linux 普通用户安装需要可用的 `sudo` 及授权，直接 root 执行则不需要 sudo。Alpine 若普通用户尚无 sudo 授权，需管理员先配置；脚本不安装系统依赖或修改 sudoers。
- 安装需要 POSIX Shell、curl、unzip、有效 CA 证书，以及 `sha256sum` 或 macOS 的 `shasum`。
- 需要交互终端输入配置、密码和确认。README 提供 `curl | bash` 快捷安装命令，会直接执行公开仓库中的脚本；如需先审阅，可先下载脚本，再运行安装命令。
- Linux 和 macOS 可执行程序统一安装为 `/usr/local/bin/yandock`，需要管理员授权，文件由 root 持有；服务仍以安装用户运行。Linux 启动脚本及安装标记位于 `/usr/local/libexec/yandock/`，由 root 持有；macOS 位于 `$HOME/.local/share/yandock/`，归当前用户所有。Linux 配置和密码位于 `/etc/yandock/`，macOS 位于 `$HOME/.config/yandock/`。安装器拒绝程序目录为符号链接及已存在的 `yandock` 目标，不覆盖已有文件。为兼容不同服务配置语法，HOME 仅支持英文字母、数字、`_`、`.`、`/`、`-`；工作目录可以包含空格、中文和单引号。

## 2. 安装

默认从 `ynhuu/YanDock` 的最新 Release 安装，也可固定版本：

```sh
sh scripts/install.sh install
```

固定完整 tag：

```sh
sh scripts/install.sh install --version v1.0.0
```

仅在需要从其他仓库安装时传入 `--repo owner/repository`。

交互过程包括：

1. 下载本机架构的 ZIP 与 `SHA256SUMS`，先校验 ZIP，再从包中提取对应二进制；缺失、校验不匹配或解压失败则停止。
2. 输入监听 IP：默认 `0.0.0.0`（所有 IPv4 网卡）；也可自定义 IPv4 或 IPv6 地址，例如 `127.0.0.1`、`192.168.1.20`、`::1` 或 `::`。IPv6 输入不加方括号和端口；安装器会在服务地址中自动补上方括号。主机名暂不支持。
3. 输入端口：默认 `8080`，范围 `1024–65535`。
4. 输入终端工作目录：默认当前用户 HOME。
5. 两次输入密码，不回显；建议使用随机长密码。
6. 查看摘要并确认；macOS 此时请求管理员授权以写入 `/usr/local/bin`，Linux 此时请求 sudo 权限。
7. 安装、启用自启动，并检查首页返回 `200`、未认证会话 API 返回 `401`。

安装器保存执行时的 PATH、HOME 和 SHELL。先确认该用户在安装终端中能够启动所需 CLI；之后改变 CLI 安装位置不会自动更新后台服务的 PATH。服务启动不会主动创建终端。

远程部署要求 HTTPS/WSS；脚本不配置 TLS、反向代理、防火墙，也不修改 Gatekeeper。默认监听所有 IPv4 网卡，安装摘要会提示远程连接风险；若只在本机使用，请输入 `127.0.0.1`。

## 3. 文件与自启动

Linux 和 macOS 的 `/usr/local/bin/yandock` 均由 root 持有、权限为 `755`，安装和卸载时需要管理员授权。Linux 启动脚本目录和 `run` 权限为 `755`，安装标记为 `644`，均由 root 持有；macOS 运行目录和脚本权限为 `700`。用户配置目录权限为 `700`。Linux 配置目录固定为 `/etc/yandock/`，内含 `settings` 和 `password`，属主为安装用户，文件权限为 `600`。macOS 的这两个文件位于 `~/.config/yandock/`。密码不写入服务配置、参数或安装日志。运行脚本读取密码并通过 `YANDOCK_TOKEN` 注入服务；它不是 YanDock 原生配置文件接口。不要提交这些目录或将其放入网页静态资源目录。

| 系统            | 自启动方式                                              | 管理位置                                       |
| --------------- | ------------------------------------------------------- | ---------------------------------------------- |
| macOS           | LaunchAgent，当前用户登录后启动                         | `~/Library/LaunchAgents/io.yandock.user.plist` |
| Ubuntu / Debian | systemd 系统服务，开机启动，以安装用户运行（允许 root） | `/etc/systemd/system/yandock.service`          |
| Alpine          | OpenRC default runlevel，以安装用户运行（允许 root）    | `/etc/init.d/yandock`                          |

Linux 服务名统一为 `yandock`，配置目录和服务名均不带 UID，只管理一个系统实例。发现已有配置目录或服务文件时拒绝覆盖，不允许另一个用户安装第二份同名服务。

macOS 需要当前用户存在图形登录会话；仅 SSH 登录、没有对应 GUI session 时，注册 LaunchAgent 可能失败。Linux 使用系统服务，不要求该用户登录桌面，也不需要启用 user lingering。

密码文件会持久保留到卸载；安装不会恢复服务重启前的登录态、终端会话或有界输出回放。浏览器断线后的进程保留与最近画面恢复属于运行中服务能力，不等于重启恢复。现有安装目录或服务文件会使脚本停止，不提供静默覆盖或自动升级。

启动失败时，安装配置可能已存在，会保留以便诊断；脚本不声称具备自动事务回滚。可通过系统服务管理器查看状态，再使用卸载命令清理。下载失败、校验失败、输入校验失败或取消最终确认时，不创建安装目录或自启动配置。

### 更新已有安装

安装器当前只有安装和卸载流程，不提供原地升级命令。不要用再次安装覆盖现有服务。手动更新前先按[使用指南](使用指南.md#7-更新停止与重启)构建或准备可信的新二进制，再停止已确认身份的服务并等待退出，替换可执行文件后沿用原设置启动；不要把密码写入命令参数或日志。

旧版 Linux 安装使用 `~/.env/bin/yandock` 和 `~/.local/share/yandock/`。新版不会自动迁移，也不使用新路径推测旧版文件所有权；请先用原安装脚本执行卸载，再使用新版重新安装并输入配置。卸载会结束终端会话，请先保存工作。

重启会结束现有终端并清空登录态和保留输出，需事先保存工作。启动后确认监听端口、首页与新网页资源可达，未认证 `/api/sessions` 仍返回 `401`；页面仍使用旧协议或资源时刷新。安装器不负责迁移 CLI 自身的凭据和会话数据。

## 4. 卸载

使用同一安装用户运行（root 安装时也由 root 卸载）：

```sh
sh scripts/install.sh uninstall
```

不需要仓库地址，也不下载文件。确认后停止服务、移除自启动及安装器创建的程序、密码和配置。停止服务会结束所属终端会话。仅删除明确的托管文件；目录中如有其他文件则保留，不递归删除目录，不删除项目目录、CLI 配置或会话数据。

## 5. Release 资产约定

发布者需上传以下 ZIP 资产。每个 ZIP 内含一个同名（不含 `.zip` 后缀）的二进制文件：

| 平台                | 资产名                 |
| ------------------- | ---------------------- |
| macOS Apple Silicon | `yandock-darwin-arm64.zip` |
| macOS Intel         | `yandock-darwin-amd64.zip` |
| Linux x86-64        | `yandock-linux-amd64.zip`  |
| Linux ARM64         | `yandock-linux-arm64.zip`  |
| Linux ARMv7         | `yandock-linux-armv7.zip`  |

同时上传 `SHA256SUMS`，每行格式为 `64 位十六进制摘要`、两个空格、ZIP 资产名。`make release` 会为当前五个目标构建 ZIP 并生成该清单；脚本只下载本机架构的 ZIP，缺失时明确失败，不回退到其他架构。

Linux 资产使用 `CGO_ENABLED=0` 构建，避免 Alpine 上依赖 glibc。`make release` 只构建本地 ZIP 和校验清单，不会创建 GitHub Release 或上传资产。前端嵌入构建必须先完成，交叉编译不能替代目标平台运行测试。

校验和用于检查下载完整性，不能替代独立签名验证；请仅安装可信仓库的 Release。脚本当前仅支持可公开下载的资产，不接收或保存 GitHub 访问令牌。

## 6. 开发检查

```sh
sh -n scripts/install.sh
python3 -m unittest discover -s scripts -p '*_test.py'
```

回归测试用临时 HOME、模拟 HTTPS ZIP 下载及模拟服务管理命令，不安装真实服务；macOS 用例将脚本副本的 `/usr/local/bin` 重定向到临时目录，不执行真实提权；Linux 用例将 `/etc`、`/run`、`/usr/local` 重定向到临时目录，不执行真实提权或属主变更。覆盖 ZIP 校验与提取、完整安装/卸载、两平台二进制安装到 `/usr/local/bin/yandock`、Linux 启动脚本安装到 `/usr/local/libexec/yandock/run`、固定配置目录与服务名、密码权限、特殊工作目录安全引用、校验失败、无效地址及端口、root 安装确认及取消确认。
