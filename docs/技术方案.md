> **三个独立边界**：浏览器断线后的进程存活已实现；最近画面通过有界回放恢复；后端重启后的会话恢复未实现。三者不能互相替代。

## 1. 定位与实现状态

YanDock · 虤坞是单用户、自托管、单开发机器上的远程终端工作台，通过浏览器操作真实 Shell 或 AI Coding CLI。保留 CLI 原有交互，不解析 ANSI 画面推测 Agent 业务状态，不建设完整 IDE。

当前处于阶段一开发预览，部分后续阶段能力已提前实现，不代表第一版已完成验收。

| 能力                                     | 当前状态                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------- |
| Go 服务、React 网页、前端嵌入分发        | 已实现                                                                              |
| 凭据登录、限流、最新登录接管             | 已实现，认证状态仅在内存中                                                          |
| 多 PTY、WebSocket 输入输出、resize、关闭 | 已实现，不设应用层终端数量上限                                                      |
| 最小空闲显示编号、标签排序与切换         | 已实现，切换不重建终端或连接                                                        |
| 断线期间进程保留、自动重连               | 已实现，重连先恢复有界输出再接实时流                                                |
| 当前终端目录 Git 更改、历史与文件浏览/传输 | 已实现，跟随活动终端目录并限制路径，支持 Git 更改、按 15 条分页加载的只读提交历史图、文件上传、下载和删除；单文件上传上限 10 MiB、下载上限 128 MiB |
| 移动布局、辅助键、触摸滚动、复制粘贴     | 已实现并有 Chromium 模拟回归，真机待验收                                            |
| 最近输出恢复                             | 已实现，每会话最多 32 KiB / 512 帧，包含尺寸事件，超限淘汰旧段                      |
| 多项目、CLI 专用适配                     | 未实现，当前只有统一的服务端程序与目录配置                                          |
| 完整终端快照、后端重启恢复               | 未实现；有界回放不保证截断后完整重建所有终端状态                                    |
| 多设备同时控制、画面广播、列表实时同步   | 未实现，采用后登录撤销旧登录的策略                                                  |

### 平台与范围

- Linux 与 macOS 均为首版正式支持目标，macOS 包含 arm64 和 amd64；目标范围不等于所有平台已完成运行验收。
- 当前主要在 macOS arm64 进行自动化运行验证；Linux、macOS amd64 及移动真机仍需独立验收。
- 不纳入当前范围：Windows、多租户隔离、SSH 网关、节点集群、双终端引擎及重启后的透明恢复。

## 2. 技术栈与部署架构

| 层级       | 当前选择                                                              |
| ---------- | --------------------------------------------------------------------- |
| 前端       | React、TypeScript、Vite、Tailwind CSS v4                              |
| 外围控件   | 当前为原生元素；shadcn/ui 尚未引入，按需评估                          |
| 终端       | xterm.js、FitAddon、WebglAddon                                        |
| 后端       | Go、标准库 `net/http`                                                 |
| 连接与进程 | `coder/websocket`、`creack/pty`                                       |
| 分发       | `go:embed` 嵌入网页，按系统和架构构建可执行文件                       |
| 验证       | Go testing/vet/race、TypeScript、ESLint、Prettier、Vitest、Playwright |

依赖版本以 `go.mod`、`go.sum`、`web/package.json` 和锁文件为准。Tailwind CSS 用于外围布局，不替换 xterm 的内部渲染；WebGL 插件仍属于同一终端引擎，不是第二套引擎。

```text
电脑 / 手机 / 平板浏览器
  React + xterm.js
          │ HTTPS / WSS
          ▼
HTTPS 反向代理
          │ HTTP / WebSocket（同机回环地址）
          ▼
YanDock Go 服务
  ├── 内嵌网页与 HTTP API
  ├── 内存认证与撤销通知
  └── 会话管理器
        └── PTY + 进程组
              └── Shell / 通用 CLI
```

本机开发和可信局域网测试可以直连 HTTP。远程部署要求认证及 HTTPS/WSS，通常由同机代理终止 TLS。浏览器无需安装 CLI；服务端必须具备目标程序、运行环境和工具。

### 数据所有权

| 数据                                    | 所有者与保留方式                                 |
| --------------------------------------- | ------------------------------------------------ |
| 凭据摘要、最新登录 ID、有效期和撤销信号 | 后端内存，重启清除                               |
| PTY、进程组、会话列表和显示编号         | 后端会话管理器，重启清理                         |
| xterm 画面与回滚缓存                    | 浏览器内存；刷新后由服务端保留的输出重建最近画面 |
| 最近输出与尺寸事件                      | 每会话服务端内存有界保存，移除或服务重启清理     |
| 标签排列                                | 当前页面内存，不改变服务端创建顺序               |
| 主题和字号                              | 当前浏览器 localStorage                          |
| CLI 凭据与 CLI 自身会话数据             | CLI 在服务端自行管理，不发送给浏览器             |

YanDock 不将终端原始输入输出持久化到磁盘。最近输出可能含命令回显和敏感信息，仅在服务器会话内存中有界保留，进程退出后保留至显式移除记录，服务重启清除；不提供配置文件或服务重启恢复。

## 3. 认证、会话与进程生命周期

### 认证与控制连接

- 访问凭据由服务端环境提供，仅最后一次成功登录有效。新登录撤销旧登录并主动关闭旧连接，但不结束 PTY；失败登录不影响旧登录。
- 同一浏览器共享 Cookie 的页面属于同一登录，但每个终端仍只有一个控制连接。重复连接返回 `409`，不强制接管。
- 旧连接释放控制位置前，新登录的连接可能短暂重试。无终端连接的旧页面在后续 HTTP 请求中发现登录失效。
- 列表没有订阅或广播接口；新登录可以获取现有会话，多个页面不保证列表实时一致。

### 当前创建与退出流程

1. 浏览器用当前字号和可视区域测量实际网格，再提交行列数。测量实例复用真实终端配置和布局，随后完整释放。
2. 后端使用服务端指定的程序、参数列表和初始目录创建 PTY，不接受网页任意指定可执行程序或路径。
3. 管理器分配唯一 ID 和最小空闲显示编号，注册会话并启动输出读取与进程等待。
4. 浏览器连接 WebSocket，验证版本二 `hello`。`replay=true` 时按历史尺寸重置并回放输出，收到 `replay-end` 且 xterm 解析排空后适配当前视口，运行中的会话才开放输入；符合条件的首次连接使用 `replay=false`，保留启动查询的正常响应。后端按连接接收顺序串行处理输入与 resize。
5. 浏览器断线只释放控制连接；重连先检查登录、会话是否存在及进程是否仍在运行。
6. 自然退出后清理资源、排空输出并通知客户端；记录保留至显式移除，编号仍被占用。
7. 显式关闭或服务退出由管理器清理进程组与 PTY；移除记录后释放显示编号。

**PTY 归会话管理器所有，不归 WebSocket 所有。** 进程可能主动脱离原进程组，因此这不是任意后代进程监管器或 Shell 沙箱。

### 最近画面恢复与边界

- 切换本页标签保留终端实例、缓存和连接。
- 断线、刷新、重新登录或换设备后，连接在同一把会话锁内截取有界回放并注册实时流；先传回放，再传后续实时输出，避免重叠或漏掉分界处的数据。
- 每次恢复先重置浏览器终端，按记录的初始尺寸和 resize 事件重放，解析完成后适配当前视口，不在旧画面上重复叠加历史。恢复期间暂停输入和自动 fit，不将回放中的查询响应写回 PTY。未截断的首次启动输出按实时流处理，保留 CLI 启动查询的首次响应。
- 每会话最多保留 32 KiB 输出与 512 个数据/尺寸帧；按完整 ANSI 和 UTF-8 边界淘汰旧段，超长未完成控制串丢弃并在安全边界恢复采集。旧内容超限时静默淘汰，协议保留截断标记，不弹出提醒。
- 未截断的回放可重建普通终端及已覆盖的 ANSI 备用屏幕场景；截断后的相对光标、样式、备用屏幕切换及更早尺寸依赖不保证完整恢复。这不是任意 ANSI 程序的完整终端快照，不含图形协议或无限历史承诺。
- 自然退出的记录仍可恢复最后保留的画面，但不能再输入。显式移除记录或服务重启后清除回放，不恢复此前的进程或会话。

## 4. 前端与移动交互

### 终端实例与尺寸

- 每个会话保持一个终端实例和控制连接；主题、字号、标签切换不重建它们。
- 初始网格由 xterm/FitAddon 和实际渲染方式测量，连接后继续通过 ResizeObserver 适配布局。外层负责留白，xterm 挂载节点不设置 padding。
- 不固定用 80×24 启动，避免旧宽度的 zsh 行尾标记及填充空格被不同宽度的网格解析而残留 `%`；不通过过滤输出或修改用户 Shell 配置隐藏字符。
- WebGL 不可用或上下文丢失时回退 DOM 渲染，不承诺回退后消除全部字符拼接缝隙。

### 状态与提示

- 工作台统一显示状态提示卡片，连接中、自动重连和正在关闭的提示独立于终端模块懒加载；无障碍状态播报保留。
- 提示颜色按语义区分：蓝色用于首次连接、主动关闭和上传进行中；绿色用于上传、删除成功；黄色用于进程结束、终端被关闭、自动重连、输入受阻和部分上传成功后中断；红色用于请求失败、全部上传失败和协议不兼容。不能用是否自动重连判断提示是否为普通信息，也不将进程结束当作成功退出。
- 状态播报由工作台统一负责；保留键盘导航、焦点管理，不因渲染反复抢焦点。
- 头部 24 小时制时间只在 Android 判断为全屏时显示：`document.fullscreenElement`、`display-mode: fullscreen` 和「布局视口高度与屏幕高度相差不超过 48 CSS px（系统栏与外壳工具栏被隐藏）」任一成立即视为全屏，并在视口尺寸、显示模式和全屏状态变化时重新判断；其他平台与普通页面不显示。WebView 外壳若既不使用 Fullscreen API、也不放大 WebView 布局，页面无法识别其全屏状态。

### Git 与文件抽屉

- 项目抽屉按设备类型布局：手机和平板全屏，其他设备靠右占视口 50%，点击外侧遮罩关闭；判定不依赖视口宽度。文件大小等次要信息仍可按窄视口隐藏。

- 项目根跟随活动终端当前工作目录，无活动终端时使用服务启动目录。页面可见时轮询目录，后台暂停并取消查询，回到前台立即同步；目录身份摘要不作为进程存活依据。
- Git 更改按文件展开差异，汇总及单文件增删行数受读取预算约束，未完成时明确标记。更改列表和文件树共用 U/A/M/D 显示映射；重命名、冲突等其他状态当前归为 M，原始两列 Git 状态仍由 API 保留。
- Git 历史在更改视图内切换显示，后端按拓扑顺序分页返回提交，每页 15 条，前端按需追加直到没有更多提交及本地/远程引用，根据父提交关系绘制分支和合并线路；点击提交读取只读详情和修改文件列表，继续点击文件读取该提交与第一父提交之间的单文件差异。文本、二进制和超限文件分别提示。暂不提供 checkout、提交、推送、拉取或分支管理。
- 展开的文件标题在对应内容范围内吸顶，支持滚动后直接折叠；悬停背景保持不透明。紧凑差异工具栏提供行数和打开文件入口。
- 文件树支持隐藏文件开关、文本/Markdown 预览、上传、下载和确认删除。长按或右键文件夹可打开上传和删除菜单：上传目标为该文件夹，删除需确认后递归删除其全部内容；不提供编辑、保存、Git 暂存或提交。单文件下载上限为 128 MiB，客户端在分配缓冲区前拒绝超限响应；下载状态提升到工作台，显示进度、完成和错误提示；同一终端的同一路径重复下载会提示正在下载，不同文件可并行下载并分别取消。超过预览大小限制的文件仍进入预览页并显示内联提示，不弹出错误提示，仍可下载原文件。系统返回键按“预览 → 文件列表 → 关闭抽屉”处理。
- 图片预览支持 PNG、JPEG、GIF、WebP、ICO、SVG，单文件最多 10 MiB。通过受鉴权的文件接口读取为 Blob，再以 `<img>` 展示；SVG 不直接插入 DOM，图片模式不执行脚本或加载外部资源。预览切换或卸载时释放 Blob URL。
- 面板读取请求按上下文取消和失效；文件树刷新最多四个并发请求，隐藏文件设置在切换终端时保留。关闭面板取消读取，不结束 PTY。大小、列表和统计限制见协议文档。

### 触摸与软键盘

- 辅助栏 Shift + Enter 发送 LF（`\n`），普通 Enter 发送 CR（`\r`）；Shift 在使用一次后关闭。输入的最终含义由服务端终端程序决定，不能承诺所有 CLI 均将 LF 作为编辑换行。

- 移动端识别覆盖 Android、iPhone、iPad，以及使用桌面 UA 的多点触摸 iPadOS；普通桌面不因窗口变窄或有触屏就启用移动复制粘贴。
- 辅助栏的键盘开关固定在最左侧；其他按键在右侧保持单行，可容纳时居中，放不下时横向滚动。具体按键与操作见使用指南。
- 仅对上述移动端设备限制终端轻点聚焦：取消触摸结束的默认激活行为，并拦截浏览器可能由触摸合成的 `mousedown` 事件，避免 xterm 获取焦点或向 CLI 发送点击操作；触摸滚动与滚轮报告保持独立。输入框默认只读，意外获焦时立即失焦；辅助栏键盘按钮解除只读并重新聚焦以请求显示软键盘，收起时恢复只读。按钮状态跟随输入框焦点；移动端优先使用可用的 VirtualKeyboard 键盘几何事件，并结合可视视口收缩/恢复同步收起状态，即使系统未触发输入框失焦；对 WebKit 延迟上报的视口尺寸复测。若浏览器既不提供键盘几何事件、也不改变可视视口，则网页无法判断系统键盘是否可见。切换会话或打开复制菜单时收起键盘。普通桌面端不启用这些拦截与只读限制，保留鼠标点击聚焦及键盘输入。
- 辅助键的方向键、Home 和 End 按目标程序的应用光标键模式（DECCKM）选择 CSI 或 SS3 编码，与 xterm 自身的按键处理一致；翻页键、控制字符、Esc 和 Tab 不随模式变化。缺少该切换会让全屏程序把方向键读成单独的 Escape。
- 后端在断线期间继续跟踪应用光标键、备用屏幕、鼠标报告/编码和 bracketed paste 模式，重新连接时先同步这些交互模式，避免刷新、退出再登录后辅助键与触摸滚动走错路径；这不是画面、全部终端模式或后端重启恢复。
- 普通屏幕滑动滚动 xterm 缓存，可有界短惯性；备用屏幕按终端行高把触摸位移换算为当前鼠标协议的行级滚轮报告，不支持时回退翻页键，不使用惯性。
- 同一触摸监听器仲裁滚动和长按，取消、新手势与卸载清理计时器、惯性和动画帧。
- 使用动态视口、`visualViewport.height/offsetTop` 和安全区适配软键盘，不硬编码键盘高度。焦点变化后有延迟复测，以适配 WebKit 延迟上报；页面不使用固定定位工作区，并限制缩放。

### 移动端复制粘贴

- 长按打开触点附近的“复制 / 粘贴”菜单；边缘自动避让，外点、滚动或切换终端关闭相应界面。
- 复制使用长按时可见区域的只读文本快照，合并自动折行；粘贴使用独立空白草稿，避免将屏幕输出误发到终端。
- textarea 使用系统选区和粘贴菜单，不调用 Clipboard API 或 execCommand。终端区域拦截原生上下文菜单，但不拦截面板输入框的原生菜单。
- “发送”交给 `terminal.paste()` 做换行转换和 bracketed paste，然后在结束标记之外附加一次回车，不受粘滞 Ctrl 影响。
- 内容与附加回车一起检查发送预算，失败保留草稿、不发送孤立回车；接受后按 UTF-8 边界分帧。浏览器排队成功不表示服务端已确认接收，不自动重发。
- 复制、粘贴面板不自动聚焦 textarea；关闭不强制弹出键盘，关闭或卸载清除临时内容。

以上移动行为有 Chromium 模拟验证，但中文 IME、系统菜单、真实软键盘和触摸手势仍需真机验收。

## 5. 协议、安全与资源边界

字段、状态码、关闭语义与具体限额统一维护在[终端协议](终端协议.md)，这里仅说明架构原则：

- HTTP 管理认证和会话；WebSocket 文本帧传 JSON 控制消息，二进制帧传终端字节。UTF-8 分块由连续解码处理，不逐帧独立转字符串。
- HTTP API 和 WebSocket 都鉴权；写请求及握手校验 Origin。代理必须保留外部 Host 和浏览器 Origin，不信任客户端自报的转发头。
- 项目文件接口以活动终端当前目录为根浏览、预览、上传、下载和删除；支持删除普通文件和递归删除目录，拒绝删除项目根及直接访问 `.git` 路径，递归删除不跟随目录内符号链接。Markdown 预览渲染文档排版，代码预览提供语法高亮、行号与窄屏自动换行。忽略符号链接与 `.git` 目录，不覆盖同名上传文件。该限制不构成终端命令沙箱。未跟踪文件的行数统计受单文件及整次请求读取预算约束，未完成统计会明确标记，不显示为准确的零行。
- Cookie 使用 HttpOnly、SameSite=Strict；TLS 或经校验的 HTTPS Origin 启用 Secure，不在 URL 携带长期凭据。
- 凭据非空即可启动，但可被其他设备访问的部署应使用随机长凭据；失败登录限流按服务全局计算。
- 不设终端总数上限，但保留每会话单控制连接、消息大小、队列、发送预算、读写超时和心跳限制。控制连接仍在时，输出队列满会对 PTY 读取施加背压；断开后解除等待并持续更新有界回放，不再保留旧连接的发送队列。
- 使用普通用户运行。工作目录校验不构成隔离；不默认记录终端内容、完整环境或凭据，不向不可信用户提供共享终端。

## 6. 工程与平台约定

- Go 包围绕认证、会话、HTTP/WebSocket 和嵌入资源划分；不提前建立空模块或无需求的中间层。
- 前端按功能分目录，UI 与连接、手势、资源生命周期分开，具体文件职责见前后端开发文档。
- 前端工作台只负责功能组装；会话导航与状态归 `sessions`，终端实例与连接归 `terminal`，Git/文件抽屉、预览与目录跟随归 `project`。共享模块不反向依赖功能，独立功能不反向导入工作台；静态导入边界由 ESLint 约束。
- 后端文件接口、共享路径规则、Git 读取和 Git 统计在 `server` 包内按职责拆文件，复用既有鉴权和会话管理器，不为文件整理增加 service/repository 层或复制资源所有权。
- 构建顺序为前端构建 → 嵌入资源同步 → Go 编译。运行中的旧二进制不会读取新网页文件。
- 生成产物、依赖目录、凭据、日志和本机配置不提交。
- macOS arm64/amd64 分别构建和运行验证；不假设 Finder、终端和后台服务拥有相同 PATH，不硬编码 Homebrew 路径。
- 已提供可选的交互安装/卸载脚本：下载指定 GitHub Release 并校验 SHA-256，使用执行用户身份运行，macOS 使用登录后的 LaunchAgent、Linux 使用 systemd 或 OpenRC；仅有模拟安装回归，真实服务与各目标平台运行验收待完成。脚本不自动发布资产，不静默覆盖已有配置；最低系统版本、签名、公证尚未完成，不建议关闭系统安全保护。具体约定见[安装脚本文档](安装脚本.md)。
