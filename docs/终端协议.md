# 终端协议 v2

本文描述已实现的 HTTP/WebSocket 协议与资源边界，包含有界输出回放，不定义多端协作、CLI 业务事件或完整终端快照。操作见[使用指南](使用指南.md)，实现入口见[后端文档](后端代码结构.md)。

### 客户端接入顺序

1. 登录获取 Cookie；后续 HTTP 请求与 WebSocket 握手均使用该登录态。
2. 获取会话列表，或提交有效初始网格尺寸创建会话。
3. 建立终端 WebSocket，按 v2 握手和回放顺序处理消息，再开放输入。
4. 根据关闭码区分登录失效、协议错误与普通断线，决定是否重连。

> 每个终端只有一个控制连接。`id` 是唯一身份，`seq` 只是可复用的显示编号；`running` 不表示 Agent 的业务状态。

### 通用响应约定

所有接口位于同一 Origin 的 `/api` 根路径，仅支持根路径部署。API 响应使用 `Cache-Control: no-store`；结构化响应为 JSON，文本预览和下载返回文件正文。无正文操作按各接口返回 `201` 或 `204`，错误正文为纯文本，不应依赖具体文案。首页不缓存，已存在的 `/assets/` 构建资源使用一年 immutable 缓存。

## 1. 认证与请求边界

| 方法与路径         | 请求                        | 成功响应                             |
| ------------------ | --------------------------- | ------------------------------------ |
| `POST /api/login`  | `{ "token": "..." }`        | `204`，设置登录 Cookie               |
| `GET /api/auth`    | 有效 Cookie                 | `204`                                |
| `POST /api/logout` | 有效 Cookie 和允许的 Origin | `204`，撤销并删除 Cookie，不关闭 PTY |

- 仅最新成功登录有效，有效期 12 小时。新登录撤销旧 Cookie，并向旧登录的终端连接发送关闭通知；失败登录不影响当前登录。
- 旧登录调用注销返回 `401`，不能注销新登录。同一浏览器共享 Cookie 的页面属于同一登录。
- 登录限流按服务全局的一分钟固定窗口计算。累计 5 次错误凭据后，后续请求返回 `429` 和 `Retry-After: 60`，此时正确凭据也暂时被拒绝。成功登录不计数、不清空窗口内失败计数。
- 凭据摘要、最新登录 ID、有效期和撤销信号都在内存，服务重启后失效。

### Cookie

名称为 `yandock_session`，Path 为 `/`，带 HttpOnly 和 SameSite=Strict。TLS 请求或已通过来源检查的 HTTPS Origin 增加 Secure；直接 HTTP 不设置 Secure。登录与注销使用相同安全策略，不把 Cookie 或长期凭据放进 URL。

### Origin 与 JSON 校验

- 会话 API 和 WebSocket 都需要 Cookie。写请求（包括登录）及 WebSocket 握手必须带允许的 Origin。
- 受保护接口先鉴权；无有效登录为 `401`，有效登录但来源不允许为 `403`。登录接口先检查来源。
- Origin 仅允许 HTTP/HTTPS，主机和端口须匹配请求 Host，不含用户信息、路径、查询或片段。直接 TLS 请求只接受 HTTPS Origin；HTTP 后端允许匹配的 HTTPS Origin，以支持 TLS 反代。
- 代理必须保留外部 Host 和浏览器 Origin；校验不读取客户端自报的转发头。静态资源可匿名获取不代表 API 可匿名调用。
- HTTP JSON 上限 16 KiB，要求 `Content-Type: application/json`（可含 charset）；拒绝未知字段、解码失败和尾随 JSON。此限制不适用于采用独立格式和大小约束的 multipart 文件上传。

## 2. 会话 API

| 方法与路径                       | 请求或响应                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `GET /api/sessions`              | 按创建顺序返回 `[{ "id": "32位十六进制", "seq": 1, "running": true }]`，无会话为 `[]`                              |
| `POST /api/session`              | `{ "cols": 80, "rows": 24 }`；成功 `201` 返回会话信息，启动失败返回 `500`                                          |
| `DELETE /api/session/{id}`       | 结束并移除会话，成功 `204`，不存在 `404`                                                                           |
| `GET /api/session/{id}/terminal` | 升级 WebSocket；控制连接被占用或已结束且无可用回放为 `409`，不存在为 `404`；已结束但有回放的记录可连接查看最后画面 |

创建示例中的 80×24 不是协议默认值；客户端必须提交有效尺寸，当前网页会先测量实际网格。列范围 `2–500`，行范围 `2–300`。程序、参数及初始目录只来自服务端启动配置，不接受网页指定。

### 会话字段与身份

- `id` 是唯一身份，不能用显示编号替代。
- `seq` 只用于标签显示，取最小空闲正整数；显式移除后可复用，已有编号不重排。列表按创建顺序而非编号排序。
- `running` 表示进程状态，不表示是否有控制连接，也不表示 CLI 正在思考、执行工具或等待输入。
- 自然退出的记录保留到显式删除，仍占用编号；重启清空记录。列表没有订阅/推送，单次响应不代表后续实时状态。
- 不设置终端会话总数上限，实际容量取决于服务端和浏览器资源。

## 3. 项目文件 API

| 方法与路径                  | 请求或响应                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/project/files`    | 可选 `session`、`path`、`hidden=1`；返回目录条目                                                                                            |
| `GET /api/project/file`     | `path`；默认返回 UTF-8 文本预览；`image=1` 返回支持格式的图片正文 |
| `DELETE /api/project/file`  | `path`；删除项目根目录内的普通文件或目录（递归删除内容），成功 `204` |
| `GET /api/project/download` | `path`；下载普通文件                                                                                                                        |
| `POST /api/project/upload`  | 可选 `session`、`path`；multipart 中仅允许一个名为 `file` 的文件，不接受普通表单字段；单文件最多 10 MiB，成功 `201`，无正文，不覆盖同名文件 |
| `GET /api/project/changes`  | 可选 `session`、`hidden=1`；返回当前工作区 Git 更改和行数统计                                                                 |
| `GET /api/project/history`  | 可选 `session`、`limit`（单次 1–100）、`offset`；返回一页只读提交历史及分支/标签引用                         |
| `GET /api/project/commit`   | `session`、完整提交 `hash`；返回提交元信息和修改文件列表                                                               |
| `GET /api/project/commit-diff` | `session`、完整提交 `hash`、文件 `path`；返回该提交与第一父提交之间的单文件只读差异                         |

`GET /api/project/changes` 接受可选 `session`、`hidden=1`，返回 `files`、`truncated`、`additions`、`deletions` 和 `statsComplete`。每个更改条目包含 `path`、Git porcelain 两列原始 `status`、中文 `label`、`additions`、`deletions`、`statsComplete`；`status` 的空格有意义，例如 `" M"`、`"A "`、`"??"`。网页上的 U/A/M/D 是显示映射，不是 API 状态枚举。`statsComplete=false` 时，行数不是完整统计，不能作为准确的零行展示。列表截断也会令汇总统计不完整。

`GET /api/project/history` 接受可选 `session`、`limit` 和 `offset`，`limit` 默认为 15，允许范围为 1–100；`offset` 默认为 0，必须为非负整数。网页每次请求 15 条，按需追加直到没有更多提交。返回 `commits`、`refs`、`truncated` 和 `refsTruncated`：提交包含完整哈希、父提交哈希、标题、作者和时间；引用包含分支、远程分支或标签及其目标提交；`truncated=true` 表示当前请求后仍有未返回的历史或提交输出受到读取上限限制，`refsTruncated=true` 表示引用输出受到读取上限限制。历史按拓扑顺序返回，只读，不执行 checkout、提交、推送或其他 Git 写操作。

`GET /api/project/commit` 接受 `session` 和完整提交 `hash`，返回提交元信息、父提交和修改文件列表。修改文件列表受输出大小限制，超限时 `filesTruncated=true`。

`GET /api/project/commit-diff` 接受 `session`、完整提交 `hash` 和相对文件 `path`，返回 `patch`、`oldContent`、`newContent`、`complete` 和 `binary`。文本内容完整时 `complete=true`；二进制文件标记 `binary=true`，网页不强行解析为文本；文本超出读取限制时 `complete=false`，网页显示截断提示和补丁。

未跟踪文件的行数统计每文件最多读取 1 MiB，整次请求共享 16 MiB 读取预算；统计阶段使用 5 秒 context，并在读取分块之间检查取消。超出预算或读取失败的文件仍保留在更改列表中，并标记未完整统计。二进制文件不计文本行数。

`GET /api/project/diff` 接受 `session`、`path`、`hidden=1`，返回 `patch`、`oldContent`、`newContent` 和 `complete`；完整内容不可用时前端回退补丁预览。

`GET /api/session/{id}/cwd` 返回目录身份摘要 `id` 和目录名 `name`。同一终端的并发目录查询合并，结果最多短时复用 250 毫秒；不能据此判断终端进程存活。

提供 `session` 时以该终端当前目录为根，否则使用服务启动目录。各项目接口均接受可选的 `session`；`path` 相对于该根。预览、目录列表和差异支持 `hidden=1`，下载与删除不通过隐藏开关授权。拒绝越界路径、符号链接和 `.git` 路径；禁止删除项目根目录。目录删除包含全部内容（含隐藏内容），不跟随内部符号链接，不提供撤销。

目录响应为 `{files, truncated}`，每个条目包含 `name`、`path`、`isDir`、`size`。文本预览返回 `text/plain; charset=utf-8`；下载返回文件正文及 attachment 响应头。

| 项目资源     | 当前限制                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 文本预览     | 最多 1 MiB，要求有效 UTF-8 且不含 NUL                                                                                   |
| 图片预览 | `image=1` 时最多 10 MiB；按扩展名允许 PNG、JPG/JPEG、GIF、WebP、ICO、SVG（大小写不敏感），返回对应图片 MIME；不支持的格式返回 `415`，超限返回 `413`。响应带 attachment 及 `sandbox; default-src 'none'` CSP；客户端通过 Blob URL 与 `<img>` 展示，不作为 HTML 插入 |
| 单文件上传   | 最多 10 MiB；multipart 总请求最多 10 MiB + 128 KiB                                                                      |
| 单文件下载   | 最多 128 MiB；超限返回 `413`，客户端不分配下载缓冲区                                                                        |
| 目录列表     | 单次读取最多 5,000 个条目后筛选、排序，超出时 `truncated=true`                                                          |
| Git 更改列表 | 最多 2,000 项；Git 状态输出最多 4 MiB，超限也标记截断                                                                   |
| Git 提交历史 | 单次默认读取 15 条；读取输出最多 2 MiB，提交超限标记 `truncated=true`，引用超限标记 `refsTruncated=true` |
| Git 提交文件 | 单次提交修改文件输出最多 2 MiB，超限也标记 `filesTruncated=true`                                                         |
| 差异         | 补丁正文最多 256 KiB，超限附截断标记；旧、新文本分别不超过 1 MiB 且有效时返回完整内容，否则 `complete=false` 并回退补丁；二进制标记 `binary=true` |

Git 功能需要服务端可执行 `git` 且目录属于可用仓库；无法读取 Git 状态、历史、提交详情或提交差异时返回 `409`，不影响普通文件浏览接口。

## 4. HTTP 错误状态

| 状态码 | 场景                                                                 |
| ------ | -------------------------------------------------------------------- |
| `400`  | JSON 解码或业务字段无效，包括正文超限、无效尺寸                      |
| `401`  | 凭据错误，或 Cookie 缺失、到期、被撤销                               |
| `403`  | Origin 缺失、`null` 或不匹配                                         |
| `404`  | 未知 API、会话已移除或静态文件不存在                                 |
| `405`  | 路由方法不允许，或静态服务收到 GET/HEAD 之外的方法                   |
| `409`  | 控制连接被占用、已结束会话无回放、上传同名文件或 Git 仓库/状态/历史不可用 |
| `413`  | 文件预览、上传或下载超过大小限制                                     |
| `415`  | 预览内容不是有效 UTF-8 文本                                          |
| `429`  | 登录失败次数达到窗口限制                                             |
| `500`  | 启动程序、生成随机登录 ID 等服务端失败，不暴露完整内部错误           |

## 5. WebSocket 消息

文本帧传 JSON 控制消息，二进制帧传终端字节。终端文本输入使用 UTF-8，二进制鼠标报告保持原始字节；输出不能逐帧独立解码为字符串，xterm 使用连续字节解码状态处理分块。

### 握手

通过 Cookie、Origin 和单控制连接校验后，服务端先发送：

```json
{
  "type": "hello",
  "version": 2,
  "replay": true,
  "cols": 80,
  "rows": 24,
  "truncated": false
}
```

尚未成功发送过 hello 的运行中会话，若启动输出未截断且没有历史 resize 事件，版本二握手使用 `replay=false`：启动输出按实时流处理，允许终端首次查询得到正常响应，不发送 `replay-end`。失败的 HTTP 升级不消耗首次连接资格，其他连接使用 `replay=true`。

回放连接的客户端验证版本后先重置终端到 `cols` / `rows`，接收有界回放。回放中二进制帧与实时输出格式相同，文本 `{ "type": "replay-size", "cols": 100, "rows": 30 }` 按顺序更新重放尺寸。服务端发送 `{ "type": "replay-end", "running": true }` 划定回放结束；客户端等此前 xterm 写入解析全部完成后适配当前视口，仅在 `running=true` 时开放输入和 resize。恢复期间产生的终端查询响应不发送给服务端。

当前网页兼容旧服务的版本一 `hello/replay=false`，该路径不提供回放。旧网页不认识版本二时应刷新。没有额外的客户端 `hello`；不要把访问凭据加入 WebSocket URL。

### 客户端 → 服务端

| 帧类型 | 内容                                            |
| ------ | ----------------------------------------------- |
| 二进制 | PTY 输入，单条最多 8 KiB                        |
| 文本   | `{ "type": "resize", "cols": 100, "rows": 30 }` |

输入与 resize 按连接接收顺序串行处理。控制消息拒绝未知类型、未知字段和无效尺寸；带非零 `version` 的 resize 也会被拒绝。无效输入或协议使用关闭码 `1008`。

### 服务端 → 客户端

| 帧类型 | 内容                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| 二进制 | PTY 输出，每块最多 4 KiB，按读取顺序发送                                                     |
| 文本   | `{ "type": "status", "message": "进程已结束", "retryable": false }` 等状态消息，随后关闭连接 |

进程仍存活但输出流中断时，状态消息为可重试，例如 `message: "输出中断，自动重连"`、`retryable: true`。`message` 只供显示，不是业务状态枚举；进程存活仍以会话 API 为准。

## 6. 关闭与重连

| 关闭码或情形       | 客户端行为                                                           |
| ------------------ | -------------------------------------------------------------------- |
| `4001`             | 登录被替换、注销或到期，停止重连并返回登录页；主动注销不显示异常警告 |
| `1008`             | 输入或控制消息违反协议，不是登录接管通知                             |
| `1000` + `status`  | 按 `retryable` 决定重连，不能只凭正常关闭码判断进程结束              |
| 网络断开或握手失败 | 重试前查询会话列表，区分登录失效、会话已移除和进程已结束             |

已打开的连接监听登录撤销，每次输入和每 15 秒心跳也检查有效性。过期最迟在下一次检查时关闭；无终端连接的旧页面通过后续 HTTP `401` 发现失效。

前端采用 1–10 秒退避，页面恢复可见或网络恢复时提前重试。同登录重复连接不接管；新登录撤销旧连接后仍需等待旧控制位置释放。无法识别的服务端消息会停止连接并提示刷新或更新，不猜测字段含义。

切换本页标签不重连。断线、刷新或换设备后，在会话仍存在时恢复有界输出；自然退出后的记录也可回放，但拒绝输入。显式移除或后端重启不恢复会话或输出。

`Attach` 在 `Session.mu` 内捕获回放及模式前缀并注册实时流。回放连接按“hello → 模式前缀 → 数据/尺寸事件 → replay-end → 实时输出/最终状态”的顺序发送；帧的分界不会改变 UTF-8 连续解码。浏览器只在旧写入回调完成后重置终端，避免上一条连接残留的解析污染新画面；收到最终状态后即使传输已关闭，也排空此前收到的数据。

模式前缀以 CAN 起始，恢复回放起点的 DECCKM、备用屏幕、鼠标及 bracketed paste 模式；之后由记录的输出继续推进状态。淘汰仅在完整 ANSI / UTF-8 边界进行；超长未完成控制串会被舍弃，其未结束的实时尾部也跳过到安全边界。`truncated=true` 表示更早的画面或状态依赖可能缺失，不是完整终端快照。当前网页保留该元信息，但不显示截断提醒。

## 7. 资源与生命周期

| 资源                      | 当前约束                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| 控制连接                  | 每会话 1 个，实际退出后释放 slot                                                                     |
| 会话回放                  | 最多 32 KiB 数据、512 个数据/尺寸帧，仅内存，超限淘汰旧段；移除或重启清除                            |
| 连接输出队列              | 64 块、约 256 KiB；连接仍在时队列满则暂停 PTY 读取并施加背压；断开时解除等待，后续输出仍进入有界回放 |
| WebSocket 发送 / PTY 写入 | 超时 5 秒                                                                                            |
| 心跳                      | 每 15 秒 Ping，响应超时 5 秒                                                                         |
| 浏览器待消费输出          | 上限 1 MiB / 1024 个待处理操作（含回放），超过时提示并断开                                           |
| 浏览器输入网络积压        | 阈值 64 KiB，拒绝时提示，不建立无界队列                                                              |
| 显式关闭                  | 先发进程组 SIGTERM，2 秒后必要时 SIGKILL                                                             |
| 自然退出                  | 清理同进程组残余进程并排空输出，排空最多 1 秒                                                        |

PTY、进程和读取 goroutine 由会话管理器持有，不使用 WebSocket 请求 context 保活；服务退出统一清理。程序自行创建新 session/进程组或 daemonize 可能逃离监管，本版本不是进程沙箱。

## 8. 当前网页的粘贴策略

以下是客户端行为，不增加服务端协议字段：

1. 移动面板将草稿交给 xterm 转换换行并添加 bracketed paste 标记（若程序已启用）。
2. 在结束标记之后附加一次回车，与内容一起检查连接及发送预算：总字节数加当前网络积压不得超过 64 KiB。
3. 验证失败时保留草稿，不发送内容或孤立回车；通过后按 UTF-8 边界拆成不超过 8 KiB 的帧。
4. 浏览器排队成功不代表服务端确认接收，不自动重发。其他普通输入仍受单条消息限制。

有界回放已由版本二定义；未来完整终端快照、持久历史或结构化 CLI 事件仍需另行定义字段、双端校验和测试，不以解析 ANSI 画面替代可靠业务接口。
